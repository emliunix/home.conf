# NFC on the M5Dial + ST25R3916 (nfcplay)

Distilled from `~/Documents/nfcplay/docs/nfc-programming-guide.md`,
`docs/card-types.md`, `board.md` and `design/1-3`.

## Hardware

- M5Stack NFC Universal Unit (ST25R3916) on **Port-A: SDA G13 / SCL G15**, I2C
  address **0x50** (400 kHz). M5Dial itself has **no PSRAM**.
- The M5Dial's *onboard* WS1850S reader (ISO14443 A/B, internal I2C G11/G12) is
  separate and unused — do not confuse the two.
- **Port-A carries only 4 wires (5 V / GND / SDA / SCL) — there is no IRQ line**
  (confirmed on hardware 2026-09-10). The vendored driver offers an optional IRQ path
  (`using_irq` / `irq`, `wait_for_interrupt()`), but it is not usable here: detect wakes
  by polling chip status over I2C (`REG_ERROR_AND_WAKEUP_INTERRUPT` 0x1C).
- ST25R3916 supports ISO14443A/B, FeliCa, ISO15693, and (at IC level) card
  emulation / NFCIP — but the M5Stack library is reader/writer-first; emulation
  would need direct low-level command work.

## Driver surface

- High level (`m5nfc` wrapper): `m5nfc_init()`, then loop `m5nfc_activate()`
  (one full-field probe per call, true on ISO-A activation), `m5nfc_deactivate()`
  to drop the field.
- Vendored `managed_components/m5stack__M5Unit-NFC` exposes raw
  `read/write_register8/16` over the same 0x50 handle, and
  `src/unit/ST25R3916_definition.hpp` has the register map. Useful ones:
  `REG_OPERATION_CONTROL` 0x02, `REG_CAPACITIVE_SENSOR_CONTROL` 0x2F (display
  0x30), `REG_WAKEUP_TIMER_CONTROL` 0x32, `REG_ERROR_AND_WAKEUP_INTERRUPT` 0x1C
  (mask 0x18), `REG_IC_IDENTITY` 0x3F, and commands
  `CMD_CALIBRATE_CAPACITIVE_SENSOR` 0xDD / `CMD_MEASURE_CAPACITANCE` 0xDE /
  `CMD_START_WAKEUP_TIMER` 0xE1.
- **Reach advanced modes through the raw-register path — no driver fork needed.**
  That was the approved approach for LPCD.

## Read + classify flow

1. Probe with a full-field activate.
2. Classify by SAK:
   - `0x20` → **Type-4 / ISO-DEP** (phone, bank card; APDU card OS)
   - `0x08/0x18/0x28/0x48/0x88` → **MIFARE Classic family** (UID/type only; keyed
     sector access intentionally out of scope)
   - `0x00` + 7-byte UID → **Type-2 NTAG/Ultralight sticker**
   - anything else → generic `NfcA`
3. Log name + codes + UID/ATQA/SAK with the **human-readable type first**, e.g.
   `Card: NTAG / Ultralight sticker (ISO-A, Type-2) [Type-2/NfcA] UID=… ATQA=… SAK=00`.

## Runtime state machine (the part that took several builds)

- **Announce exactly once per absent→present edge.**
- **Latch "present" across the poll's own internal field gaps.** Treating the
  field-off gap as a removal caused announce/remove churn every cycle, which also
  overwrote the capture ring — the bug looked like "missing reads".
- Declare removal only after ≥3 consecutive real probes see nothing, then re-arm
  so the next placement announces.
- One soft beep per placement is UX only; never use audio as detection evidence.
- A periodic idle heartbeat line keeps the log provably fresh and exposes a dead
  app immediately.

## Low-power (LPCD) — the pitfall worth remembering

**Do not implement low-power idle as "deactivate field, sleep, periodically
re-activate".** On this stack, `m5nfc_activate()` after a long (~1.5 s+) field-off
**does not detect a card placed while idling** — reproduced with a card physically
static on the sensor (`tag=0` for the whole window). Duty-cycling the full field is
therefore broken for runtime detection, no matter how good the idle log looks.

The chip-supported path is real LPCD: field off, on-chip capacitive/phase presence
sensing plus wake timer (registers above), and only on wake run the full activate.

### Which wake source is safe (measured 2026-09-11)

In LPCD wake-up mode the **antenna-coupled detectors (amplitude, phase) drift with the
environment**, while the **capacitive sensor stays on its calibrated baseline**. One
measured day on an M5Dial: after ~8 h idle the amplitude/phase references stepped
(`ampl 0x17 → 0x20 d=9`, `phase 0x97 → 0xB4 d=28`) inside ~25 minutes in the evening and
stayed there — `ign_p` went 0 → 31,504 in ~4 h (~4.7k events/h) — while `cap` never moved
off its `0x7C` calibration (`d=0`) and the device logged **zero wakes**. With Δ=2 and
amplitude/phase in the decision that step alone would have produced thousands of
false wakes/hour.

Practical rules: (a) put **capacitance only** in the wake decision for passive tags;
(b) keep amplitude/phase *measured* for telemetry, not for decisions; (c) if they are
ever needed back, they require environment compensation or a re-reference on drift —
and (d) calibrate the cap sensor (`0xDD`) with an empty antenna, ideally on each re-arm.

## Capture and evidence (NFC-specific)

- Use the no-reset RTT monitor + host-side appending log (`build-flash-monitor.md`);
  a short bounded capture started after the human taps will usually miss the event.
- The on-chip ring is ≈1 KB and overwrites: events lost to the ring are not proof
  of "not read".
- A phone placed on the sensor at reset does not re-activate — it needs a fresh
  presentation after the field drops.
- Back up tag contents before any write experiment (reads are safe).
