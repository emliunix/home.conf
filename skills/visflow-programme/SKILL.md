# Start a programme

A question that does not fit an existing tree gets its **own root directory**, never a round inside someone else’s.

The file set arrives **as its stages arrive** — `README.md`, `grounding.md`, `verification.md` + `mutations.md`, `plan-round-1.md`, a probe directory, `results/`, `tests/`, `evaluate/round-1.md`, `decisions.tsv`. Create what the stage needs; **name the files you have not created yet and why**, rather than leaving the absence silent.

A question that spans two trees (semantics in one, price in another) belongs in a new directory: a round in either answers only half.

## Starting a programme, and extending its record (the full protocol)

*Moved here from `method.md` when that file became a manifest (2026-09-19).*

A question that does not fit an existing tree gets its **own root directory**, not a round inside
someone else's. Nothing said so until a reader asked where a cost experiment would live and had
to infer it; the required file set is `README.md`, `grounding.md`, `verification.md` and `mutations.md`,
`plan-round-1.md`, a probe directory (`probes/` or `temporal/`), `results/`, `tests/`, `evaluate/round-1.md`
and `decisions.tsv` -- the set a programme carries **as its stages arrive**, not all at once. The earlier
claim that it is "the set every open programme already has" was false and a reader checked: `loop-surface`
has neither a `verification.md` nor a `mutations.md`, and `catch-surface` has only `grounding.md`. What the
convention buys is that a reader can enumerate by `ls` and **tell what is missing and why**; a new tree should
therefore name the files it has not created yet rather than leave the absence silent. A question that spans the hypothesis
harness and the production runtime belongs in the new directory: the harness measures semantics, the
runtime measures price, and a round in either tree answers only half. *(pstack:
`principle-foundational-thinking` -- subtraction before scaffolding, the file set arrives as its
stages arrive, and a question that spans two trees gets its own foundation rather than a round
inside someone else's.)*

### Extending a programme's record

The worked procedure lives with the programme it extends: for `loop-surface` it is
`loop-surface/README.md`. The pattern is the same everywhere -- create the record file, append its row
to the table, regenerate what is generated, and hand-edit the counts a test pins -- and it was written
down only after a reader reconstructed it from the code and reported it missing.
