# learning-loop: design and evaluation

`learning-loop` is an explicitly invoked procedure for turning completed work into project-owned
records and mechanisms. It is separate from `flow-retro`, which owns a specific design lifecycle.

The skill keeps its entry procedure short and loads three references only when needed: the concern
catalog for scenario selection, routing for disposition, and transfer checks for proportional
verification. Its main safety property is subtraction. Low-learning work may produce no durable
change.

## Evaluation dimensions

| Dimension | Question | Evidence |
| --- | --- | --- |
| Trigger | Does explicit retrospective language select the skill while ordinary work stays silent? | Entry-only classification over canonical, trap, and paraphrase cases |
| Procedure | Does the full body improve evidence use, concern selection, lesson schema, routing, encoding, and provenance over control and entry-only? | Three blinded arms over one frozen rich fixture |
| Induction | At equal outcome, does the saved mechanism reduce a future reader's work enough to pay for the loop? | Control versus full output, then a bounded transfer task |
| Ablation | Do the concern catalog, routing step, structural check, and transfer check each change the result? | Full-minus-one-part samples over the same fixture |
| Walk | Do every named destination and verification level resolve against the package and fixture repository? | Read-only path and command walk |

The package follows `flow-skills-eval/design/03-skill-package-format.md`. `tests/frozen.lock.json`
pins the behavior-defining skill, references, cases, and fixtures. Trial records self-identify with
their output digests in `tests/records/`. Run `python3 tests/l0.py` from this directory after any edit.
