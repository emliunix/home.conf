# Design 07 review (independent seat: Sonnet; author: Opus), 2026-10-14, verbatim

Review of design/07 (read-only; one throwaway SWI-wasm probe in /tmp/rv07 and doc-verify/, deleted afterwards).

BLOCKING

B1. Persistent cache key ignores atom-key identity (Rationale, last para: "the path is part of the atom key ... edited heading changes the key and invalidates the cached answer"). The cross-run cache is keyed by `{model, question, labels, evidence sha, policy}` (engine/oracles.ts:159-160 and :341-344), not by atom key. Atom key only keys the in-run OracleStore. If the "Where:" text is not added to both cacheKey sites, a renamed ancestor heading serves a stale answer. Amend: state that the rendered Where: block is hashed into both cache keys, and add a verification row: "edit an ancestor heading; the next check re-asks (`asked` count > 0)". Without this the invariant 6 claim is false as built.

B2. `core.path` is not "one more ground argument". Module-source args reject non-list compounds (checker.ts:432), so `core.path(D, cell(R,'Failure witness'), ...)` in the Model example and in the YAML example never loads. It needs a dedicated literal kind like `present` (checker ~351, translate.ts:166/344/449, kernel.ts:48 SANDBOX_PRIMITIVES, core_lit_text_ and core_prove builtin clauses at core.pl:439/649; without those the proof/trace path breaks). Feasible, but amend Scope to say so. Prefer flat args: `core.path(D, R, Column, Kinds, P)` and `core.path(D, S, Kinds, P)` for sections. N as a compound term in rules stays unneeded.

B3. Row key and column position are host-side structure (invariant 7). `core.header` is a deduped set with no position (facts.ts ~140), cells are not facts, and "first column's text unless the companion names a key column" is a host decision. Amend: expose neutral facts only (`core.header_pos(D,T,Col,N)`, `core.cell_text(D,R,Col,Text)`), and let the rule name the key column, e.g. a `row_key('Property')` kind in Kinds. No default key choice in the host.

SHOULD-FIX

S1. Echo rule (Model, "The echo rule") is not statically checkable: labels are static, step text is run-time, so "text can equal a label" is true of every path. Precise replacement, two parts. Static: a `choose` oracle with `context:` bound by a `core.path` whose Kinds include `row` or `row_key` is refused unless the oracle sets an explicit `context_may_echo: true`. Run-time: at render, if any label (case/punctuation-normalised) equals or is a whole-token substring of any step text, the atom is not asked and yields a named finding "echo: label X appears in context". Also fix the wording: E1 put the Property cell in the evidence; the design must say why the same population in context behaves the same (labels = property names, row key = property name). That is the same echo, but unmeasured.

S2. Key round-trip failures are real, not hypothetical. Probe against SWI-wasm: write_term(quoted) leaves `été`, `日本語`, `αβγ` unquoted, but host `quoteAtom` (terms.ts) quotes anything not `^[a-z][A-Za-z0-9_]*$`, so kernel key and host key differ. Tabs: SWI writes `\t`, host keeps a raw tab. `hostAtomKey` re-normalises via parse and rewrite, so demands are probably repaired, but the answer path (answersFromStore → kernel) is not covered. The design's witness ("two atoms share a key") names the wrong failure; the actual one is an unrouted answer (atom shows `unasked` after being answered). Amend the round-trip test to compare kernel `core_atom_key` against host `oracleAtomKey` over Unicode, tab, backslash, quote, backtick, NBSP and 500-char headings, and print the mismatching pair.

S3. Phase 0 slug parity claim ("the segmenter's own slug function ... agree") is false. Segmenter ids are `parent/slug` with one GithubSlugger per parent (segments.ts:47-59), and depth-1 titles are not in the id. GitHub anchors use one slugger per document, so duplicates get `-1` globally and nested ids differ. Amend: run a separate document-global GithubSlugger pass over all headings for `#slug` resolution; keep `core.path` on heading text. Also: fragments `#L12`/`#L10-L20` are code-line anchors, skip them; non-.md targets are skipped; numbered headings (`## 7. X`) need matching by both slug and `normalizeSectionId` (normalize.ts), declared in advance.

S4. `§Heading` parsing is under-specified. Corpus forms are "design/05 §Oracle toolkit: ...", "model §3", "§9", "§C1-receipt": no heading end delimiter, often no document name (`§3` refers to the doc or an unnamed model), numeric sections that are not headings. Amend: phase 0 checks only (a) `#frag` links and (b) `§` references immediately preceded by a resolvable document (a link, a path or `design/NN` shorthand) within the same sentence; match by the longest heading prefix of the following text (case-folded, punctuation-stripped), never fail on bare `§N`. Preregister the false-positive count on this repo's existing prose (corpus has ~35 `.md#` links and ~50 `§` uses; label them first).

S5. Fragment checking needs target content; `DocumentInput` has only `exists(path)`. Say how: a `readTarget` host callback, per-run memo by path+mtime, restricted to the candidate tree. "Targets outside the checked set" (a cited doc that is not in the check) must be an explicit case: read-only, headings only. Also emit it as a fact in the existing `dangling` family (kind `fragment`) rather than a host-made finding, so the finding stays a rule/constraint (invariant 7); "closest headings" repair text may stay host string-distance.

S6. Gates. Phase 0 gate is decidable (labelled dangling set). Phase 1 gate "spine against no spine" has no bar, no metric and no stated threshold for "helps". Round 9 set a numerical bar for item 11; do the same: per-oracle flips (correct→wrong) allowed = 0, `evidence_reasons` gain required ≥ N rows on a labelled set, repeats = 2. Phase 2/3 gates ("lists are the grain", "evidence_reasons gains") are decidable from phase 1 only if phase 1 reports per-oracle results and a list-grain fixture census; unmeasured today: how many shipped oracles take list evidence, context byte cost vs the `max_bytes`/state budget, and key-length growth. Add these to phase 1's record. The path also includes whole `table([...headers])`, so any header edit invalidates every row's answer; consider dropping `table` from default Kinds.

S7. Verification table. Row "Kernel gate holds" is inverted: removing `core_path/4` from SANDBOX_PRIMITIVES should make a `core.path` module print `rejected`, so the witness should read "with core_path/4 absent, the boundary test prints `rejected` for a module using core.path (expected); with it present, it prints `rejected` (defect)". Mark it (phase 1); `boundary.test.ts` exists but has no core.path seed. "Path survives quoting" and "Context is not the subject" witnesses are not printed output; rewrite as the specific line the test prints. Phase 0 "check prints PASS": report.ts has PASS, confirm the CLI line; `paths-resolve` is named but not located in code (lib/references.yaml probably); verify before citing.
