# Design 06 — independent review (verbatim)

Seat: a Sonnet subagent (the author's draft was written on Fable); read-only; 2026-10-13, before
the design's first commit. Verdict: commit after amendments. The amendments taken are listed in
the design's `## Review`.

1. Problem statement, count. The design says the TypeScript evaluator fails "14 of 23 witnesses" and that the conformance runner prints "14 S2 failures". Round 2 (`round-2-verdict.md`) says 10/24 pass and 14 fail of 24. Round 4b has 23 witness files, of which S1 passes 23 and S3 passes 20 plus 3 refined or expected-failure, so the numbers differ by round. Amendment: state "14 of 24 (round 2)", cite round 2, and say which witness set each count is for. Also say that 11 of the 14 failures are the model moving beyond design 04 and only 3 are design 04's own over-demand. That affects what "parity" can mean (see 5).

2. Supersession and constitution (Decision, Review). AGENTS.md requires a numbered design to name the sections it supersedes and to amend the constitution line it touches, citing the design. Design 06 does neither. It has no "Supersedes" statement, and the Review says only "rounds 11-14 will amend this design". It never says which sections of design 05 it overrides. At least these: 05 §Kernel's "The host never evaluates a rule" and the driving-loop wording; §Module language ("refuses nothing else", versus the language break rule in 06 Model); 05 Verification rows "Trust boundary", "Open vocabulary" and "Oracle split", which grep or run against probe paths; and the `runProgram` seam in design 04. Amendment: add a "Supersedes" list of section by section with the exact replacement. For the constitution, either name the line touched (invariant 5 "In force ... under swipl-wasm 8.2.2" and its "Not covered" list move from probe to production; invariant 3's "prefix is the default policy"; invariant 7's host table facts, since `core.table/3` is "computed in the host for now") and amend it citing 06, or state "constitution unchanged by this design; amended by the step-4 verdict" and why. Note that AGENTS.md says an amendment comes from a verdict, not a plan. So a statement that the lines are not touched until round 14's verdict is acceptable, but it must be written down.

3. Machine-readable companion (yaml). The yaml has no `status` or `supersedes` field. Design 05's yaml has none either, so this is not a break, but the markdown carries Status twice in different places: top in 06, bottom in 05. The yaml `depends_on` omits `design/04-modular-verification-language.md` (the seam and TS evaluator it replaces) and `docs/doc-verify-model.md`, both of which 05's yaml lists. It also omits the worklog verdicts it cites. Amendment: add 04 and the model to depends_on. Move "## Status" to the end for consistency with 05, or confirm that the status-from-section rule accepts either position.

4. Claims versus records (Model, Decision). The mock-judge check passes, but with one warning: `kernel2/translate.mjs` is flagged as a path that does not exist (it lives at `worklog/kernel-trials/probe/kernel2/translate.mjs`). Amendment: write the full path, or drop the backticks. Uncited claims to fix: "the corpus (26 documents)" and "23 witnesses" have no round cited (4b gives 26 documents and 23 files; round 5 gives 48 witness steps). "Round 1 K3" is cited for the proof-tree meta-interpreter. "Tables abolished per step (visflow design 20 F15)" is cited correctly (round 2 verdict). The "sandbox gate (round 5)" is correct. "Per-atom (round 6)" is correct, but the design omits that the four `module-*` libraries pin `batched` and one module page demotes under per-atom; step 2's parity on the corpus will hit this. Add a sentence on that, citing round 6 "Left unmeasured". The design also cites nothing for "kernel passes ... the brute force and property tracks, the corpus, and the boundary round". Round 7–10 preregistrations exist untracked in git status (property track, `run-property.mjs`), so the "property tracks" claim is not backed by a committed verdict. Amendment: cite only rounds with verdicts (2, 4b, 5, 6) and either drop "property" or name the round-7 record as pending.

5. Clingo (Scope, Verification). Clingo is called a "differential reference only" and kept out of scope. The decisions row and the 4b verdict say S3 stays as the differential reference and gate-ledger rows `--s3` and `--s3 --random 500` remain. The design never says whether those gates stay green through migration, or that S3 is the only second implementation which agrees with the model's decided part (TS fails 14). That matters because the "differential gate" in the verification table treats the TS evaluator as the reference ("the kernel's is the one the model's reference contradicts"). But the TS evaluator is documented as "a subject, never a baseline" (decisions row 2026-10-12), and the corpus parity row only diffs verdicts between TS and the kernel. Where the TS evaluator is known to be wrong (the 11+3 failures), "parity" is the wrong target: the expected divergence set should be listed. Amendment: add a row or paragraph "known divergences = the 14 round-2 failures, each classified; parity means no divergence outside that set", and keep `--s3` gates in the migration's predicate.

6. W3 sequencing (Decision). The four steps map to rounds 11–14 but only the verification table, not each step, names a gate predicate. Step 1 -> row "Seam fills the report"; step 2 -> witness and scripted corpus parity; step 3 -> live parity (the lead runs it by hand once, so it is not a gate that can be re-run); step 4 -> deletion. Problems: (a) the default engine flips "at step 3's verdict" while step 3's live parity is manual with "cache off, both engines", so the flip has no re-runnable command; (b) no step names a rollback or says what happens if step 2 finds a divergence; (c) the tooling hooks, `npm test -- engine-golden` and `npm test -- report diagnostics`, are not shown to exist. Amendment: add a table "Step | gate predicate (command) | verdict file | flip/rollback", with a seeded defect per step (R6: for each gate, name the defect that turns it red). Run the step-3 live parity as a recorded command with its output file in `results/`, as rounds 4c and 6 do.

7. Verification table, witness cells. Checking against `witness_observable_in_row` (a cell holds only if it names what would be seen; restating the claim, or naming only that a check exists/passes/fails without saying what would be seen, fails it). Rows likely to fail: "Deletion complete" ("`evaluate.ts` or its tests remain" is observable, fine). "Cost" is fine (a threshold). "Seam fills the report" is borderline (which field, and how is "differently shaped" observed?). "Boundary carried over" ("a module that reaches the host, or runs past the budget, under the production path") only restates the property and names no concrete seed or observable. It should cite the round-5 seeds E1/E9/E17/E18 and name BLOCKED/rejected output. "Language breaks listed" ("a module the kernel rejects without a listed break") names no observable output and the "census" command has no named script. The mock judge passed all rows (0 semantic calls), so this is a prediction against the shipped oracle, not a measured one. Also: three commands are not real: `--engine ts|kernel` does not exist in `cli.ts` (design depends on it, so it should say "to be added in step 1"), `npm test -- engine-golden` and `doc-verify check --all --profile draft` timing are untested forms, and "the static-check census over every `.doc-verify.yaml` rule's modules" has no script. Amendment: mark each non-existing command "(added in step N)" and rewrite the weak witnesses as a concrete printed output.

8. Public-repo hygiene. I found no live endpoints, accounts, credentials, ports, or home paths in the design. It names `jev` nowhere, only "production judge", which is fine, and the yaml names none. The committed `.doc-verify.yaml` already contains a judge model name, so nothing new is exposed. No amendment needed beyond the path fix in 4. One caution: step 3's "live parity" output files in `results/` must not include judge endpoints or evidence text outside the outbound policy; say that the live run records results only.

9. Cost row. "slower than 2x the TypeScript engine's at draft" has no measured basis. Round 1 K4 gives 46–105 ms per corpus including startup, which is already close to the TS engine's cost, and round 5 adds 6% budget overhead. A 2x threshold is arbitrary and unreviewed. Amendment: either cite the K4/round-5 figures as the baseline, or mark the threshold as a pre-registered guess for round 11 to set, and add swipl-wasm startup cost per instance (fresh instance per check, per Model) explicitly.

10. Undecided items not stated. The design has no "Left undecided" list, and the Review says only "Not yet reviewed". Open items it should name, since they are already in the records: (a) whether `cheapest-evidence` and `most-pruning` ever ship (round 5, unmeasured); (b) the four `module-*` libraries pinned `batched` (round 6); (c) translator quoting as a separate gate (round 5 "Left unmeasured"); (d) native SWI-Prolog and memory beyond the budget (round 5, invariant 5 "not covered"); (e) the judge-side outbound policy is not part of this migration but still gated by `npm test -- semantic confidentiality`; (f) the relevance gap in `witness_observable_in_row` (round 4c, swapped fixture passes 14/14) — relevant because this design's own table would pass it; (g) D1-incomplete demand in S3 and the S1 "38 programs" D1 gap (4b) — the kernel migration inherits the S1 gap; (h) memory of one WebAssembly instance per check at scale. Amendment: add a "Left undecided" section listing these, each with the round that left it open.

11. Duplicated and misordered sections (structure). There are two "## Goal" sections: the first is the design goal, the second a pointer ("Goal 04, workstream W3; R1, R2, R5") that cites roots R1/R2/R5 where the constitution's R1 is "Judge probabilities are not calibrated", R2 "Batched answers are correlated", R5 "Oracle discrimination" — none of which is "a trusted kernel", "the constitution governs", or "the loop". Those R-labels seem to come from goal 04, not the constitution, which is a confusing clash. Also the "Rationale" says "the constitution's R1 rejects" hand-building an unverified evaluator — the constitution's R1 does not say that. Amendment: remove the duplicate Goal section (design 05 uses `## Goal` as a one-line link to `goals/04-trusted-kernel.md`; follow that), and either cite goal 04's R1 as "goals/04 R1" or reword, because the constitution roots are R1–R6 with different content.

12. Status and Review. Status "draft" is right for an unreviewed design. The Review section says "Not yet reviewed", which meets the form but not the AGENTS.md rule that the independent seat's review is appended before a run; fine for a design, but cite this review file once it exists (`worklog/kernel-trials/results/round-11-...`), and note that design 05's Review also claims "a design review is owed before status moves".

Verdict: commit after amendments — the migration plan itself is sound and consistent with the round 2/4b/5/6 records, but it must name what it supersedes and the constitution line (or state it leaves it for the step-4 verdict), fix the 23/24 count and the false R1 citation, give each step a re-runnable gate predicate with a seeded defect, and list what is left undecided.
