# Round 11 — section references are checked (design/07 phase 0)

Plan written 2026-10-14 by `lead` before any implementation; labels and the fixture
(`probe/fragment-fixtures/`) written the same hour, before the build. The independent seat's review
is appended under `## Review` before the run.

## Hypothesis

A reference that names a section of another document, as a link fragment (`doc.md#slug`) or as a
document-qualified `§Heading`, can be checked against that document's headings with **no false
finding** on this repository's 28 checked documents and **every** dangling one found, while bare
`§N`, id forms and code spans are never flagged. Refuted by: any finding on a reference labelled
`resolves` or `skipped`, or any labelled `dangling` reference without a finding.

## Axis

This is a feature round with one candidate: the gate is the labelled set. The design choices it
could turn on (the slugger's scope, the `§` matching rule) are fixed below so the labels test
them, not a tuned implementation.

## The candidate (design/07 §Model "Section references"; the review's S3–S5)

1. **Fragments**, on Markdown links only (a backticked path is an example, not a link): a target
   ending `.md` with `#frag` resolves when a document-global `GithubSlugger` pass over the target's
   headings yields `frag`, or `frag` equals a section id under `normalizeSectionId`. A bare `#frag`
   resolves against the document itself. `#L<n>` and `#L<n>-L<m>` are skipped; non-`.md` targets
   are skipped; a missing file stays the existing `link` dangling finding, not a fragment one.
2. **`§` references**, outside code spans and fenced blocks: a `§` is checked only when a resolvable
   document precedes it in the same sentence (a Markdown link, a backticked or bare path ending
   `.md`, `AGENTS.md`-style bare names that resolve, or `design/NN`); the nearest preceding one
   binds. The text after `§` is folded (lowercase, punctuation to spaces, spaces collapsed). It
   resolves when some heading H of the target has its folded tokens as a prefix of the text's
   tokens up to the sentence end, or the text's tokens up to its first punctuation mark are a
   non-empty prefix of H's tokens. Never checked: a `§` whose first token is an id or number
   (`^[A-Za-z]?\d+([.-]\w+)*$`, e.g. `§3`, `§9`, `§C9`, `§C1-receipt`), `design NN` without a slash,
   a document not resolvable as a file.
3. **Facts and rule:** a miss is `core.dangling(D, S, Target, fragment)` with Target the reference as
   written; `doc-verify:references` gains a constraint `fragments-resolve` forbidding it, severity
   `error`, message naming the reference and repair naming up to three closest headings
   (string distance, host-side text only).
4. **Reading targets:** a `readTarget(repoPath)` host callback returning the file's text, memoised
   per run by path; headings only are used; restricted to files in the repository tree.

## Predicate

```sh
npx vitest run doc-verify/tests/references/fragments.test.ts       # the fixture: 10 dangling found, 10 resolves + 7 skipped silent
node doc-verify/dist/cli.js check --all --profile draft --format json --output /tmp/r11-all.json   # the corpus
node worklog/kernel-trials/probe/fragment-fixtures/score.mjs /tmp/r11-all.json                       # labels vs findings; complete flag
```

`score.mjs` (built in this round) reads `labels.yaml`, prints one line per labelled reference with
`found`/`silent` and its label, then `false findings N`, `missed N`, `complete: true|false`
(false when a labelled reference cannot be located in the documents), and exits non-zero on any
false finding or miss.

## Seeded defects (each must turn the predicate red)

- resolving fragments against the segmenter's section ids only (no document-global slug pass):
  the fixture's `design/05-trusted-kernel-redesign.md#kernel` becomes a false finding (its section
  id is `design/kernel`);
- the `§` id rule removed: `model §9`/`§C1-receipt` lines produce findings (`skipped` violated);
- the code-span skip removed: the fixture's code-span `§Nowhere` produces a finding.

## Left unmeasured

External URLs; anchors defined by explicit HTML ids; headings generated by tools; cross-document
`§` references whose document is named only by prose ("the model §3").
